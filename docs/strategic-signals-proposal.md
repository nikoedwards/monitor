# 组织与战略信号

## 目标

把招聘组织推演从岗位数量展示升级为跨板块战略研判。招聘数据只作为证据源之一，一级卡片只回答：公司当前正在做什么、哪些信号相互印证、下一步应核查什么。

## 一级单屏

- 标题：组织与战略信号
- 顶部状态：战略姿态（扩张 / 承压 / 转向 / 观察）、全量历史、最近有效数据日期、覆盖板块
- 核心结论：一句话总判断，最多 3 条战略信号
- 主视觉：中心公司节点，外圈连接招聘、用户之声、销售、营销、网页动态；连线只代表可回溯的跨来源证据
- 底部：关键时间线、覆盖状态、展开证据与方法

人数区间、部门和地区推断、原始职位、证据链、模型权重和限制条件全部下沉到二级详情。

## 数据边界

- 默认使用全量历史；用户主动切换区间时才使用 `start_date` / `end_date`
- 单一招聘来源只能形成“招聘观察”，不能升级为战略信号
- 战略信号至少需要两个独立来源组；缺失数据显示覆盖不足，不解释为负面
- 所有模型字段必须绑定可解析的 evidence ID，服务端校验后才允许展示

## API 草案

```text
GET /api/hiring/strategic-signals
  brand_id
  scope=all_history
  start_date / end_date
  refresh
```

返回 `window`、`headline`、`signals`、`coverage`、`timeline`、`details` 和 `caveats`。`details.organization_estimate` 承载人数、部门和地区区间，不进入一级摘要。

## 信号结构

每条信号必须同时包含：事实观察、可能含义、业务影响、替代解释、下一步验证条件、时间窗口、方向、优先级、置信度、涉及板块和 evidence IDs。

模型只生成结构化研判；事实、日期、数字、来源链接和证据归属由服务端从数据库校验，不接受模型自行编造。

## 验收门槛

1. 一级卡片一屏完成阅读，最多 3 条信号。
2. 默认不受招聘页 7/30 天筛选器影响。
3. 人数区间只在二级展示，并标注估算、假设、置信度和限制。
4. 每条信号至少有两个独立来源组，且证据可跳转到真实明细。
5. 事实和研判分层，支持查看替代解释和下一步验证信号。
6. 空数据、单板块数据、采样不足都有明确状态。
7. 历史读取有上限、抽样和缓存，接口耗时不会随历史无限增长。
8. 桌面和移动端都能完成一级阅读。

## 实施顺序

1. 统一跨板块 evidence schema 和独立来源组校验。
2. 在现有 overview evidence 基础上增加全量历史模式和缓存。
3. 增加 strategic-signals API 与结构化模型适配器。
4. 替换招聘页现有组织推演一级视觉，保留二级估算详情。
5. 添加接口、证据校验、空数据和渲染回归测试。
6. 先隔离环境验收，再决定是否发布生产。
