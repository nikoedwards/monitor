# 组织与战略信号：本地实现草案

> 评审范围：招聘页现有“业务动向分析”下方的一级单屏模块。招聘是证据源之一；战略研判必须联合用户之声、销售、营销和网页变化。本文只定义接口、证据校验、布局草图和测试清单，不修改生产代码。

## 1. 产品边界

一级模块命名暂定为“组织与战略信号”。它回答三个问题：

1. 公司最近一段完整历史里，哪些方向最值得关注？
2. 哪些方向由多个独立板块共同支持？
3. 下一步应该观察什么来验证或推翻判断？

招聘岗位数、公开员工样本和模型人数区间只属于二级详情。一级屏显示“招聘信号”“可见人员样本”和“可能的组织变化”，不把它们写成真实 headcount。

## 2. 一级接口契约

建议新增：

```text
GET /api/hiring/strategic-signals
```

参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `brand_id` | 必填 | 当前品牌 |
| `scope` | `all_history` | 默认读取当前品牌各板块最早至最近有效日期 |
| `start_date` / `end_date` | 空 | 用户切换到自定义窗口时覆盖 `scope` |
| `refresh` | `false` | 是否绕过模型缓存重新研判 |

### 接口实现建议

- 复用 `server/overview_evidence.py` 的来源地址化证据包和 `validate_overview_insights` 的引用校验。
- 在证据包上增加 `scope=all_history`：先找各板块有效数据的最小日期和最大日期，再以统一窗口构建跨板块数据。没有数据的板块必须保留 `status=empty`，不能被默认为负面。
- 继续使用按实体、平台和独立来源组的抽样上限；全量历史只改变日期范围，不取消上限。
- 通过持久缓存保存模型结果，缓存键至少包含 `brand_id/scope/start/end/evidence_version/model_version`。
- `signals` 是一级可展示结果；`details.organization_estimate` 只作为二级按需加载或显式“展开推演”的结果。

## 3. 证据校验规则

### 3.1 统一证据字段

每条证据至少归一化为：

```text
id, source_domain, source_type, independence_group,
entity_key, observed_at, collected_at, title, fact,
metrics, url, record_id
```

招聘岗位可以使用 `entity_key=department:city:role_family`；用户反馈使用产品/平台/主题；销售使用 listing；营销使用广告/渠道；网页使用 monitor/page。缺少实体键时只能作为背景证据，不能单独建立跨板块关联。

### 3.2 信号通过门槛

- 跨板块战略信号至少引用两个不同 `source_domain`，并且至少两个不同 `independence_group`。
- 同一模块的汇总指标和原始记录属于同一来源组，不能算两份独立支持。
- 市场份额、情绪汇总、招聘岗位数等派生统计必须标记 `independence_group=derived`，不能单独构成交叉验证。
- 每个 `evidence_id` 必须能在服务端证据目录中解析；非法 ID 直接丢弃该引用。
- `observation` 只允许事实；`inference`、`business_impact` 和 `alternative` 才允许谨慎推断。
- `first_seen` 只能表示首次被监控发现，不得自动写成实际发布、上线或入职日期。
- 相同时间戳达到批量阈值时，增加“可能批量入库/日期回填”的 caveat，禁止推断集中发布。
- 证据不足的模型卡片不降级为“看起来合理”的文案，直接不展示并给出缺证据原因。

### 3.3 置信度规则

| 级别 | 默认条件 | 一级展示 |
| --- | --- | --- |
| 高 | 至少 3 条核心证据、跨至少 2 天，且有两个独立来源组 | 可进入重点信号 |
| 中 | 至少两个独立来源组，但样本量或时间重复不足 | 可展示，必须带“待验证” |
| 低 | 单板块、单条证据或仅关键词推断 | 不进入默认重点，可在筛选中查看 |

模型返回的 confidence 只能在服务端校验后保留，不能把模型自报置信度当作事实。

## 4. 一级单屏布局草图

```text
┌─────────────────────────────────────────────────────────────┐
│ 组织与战略信号   全量历史 · 2025-01-01—2026-11-15  [重新研判] │
│ 当前姿态：可能扩张       中等置信度       最近数据：11-14      │
├───────────────────────────────┬─────────────────────────────┤
│ 总判断                        │ 数据覆盖                    │
│ 可能正在扩大海外商业化投入    │ 招聘 ● 用户之声 ● 销售 ◐      │
│ 由招聘、营销、网页变化共同支持 │ 营销 ● 网页变化 ●             │
├─────────────────────────────────────────────────────────────┤
│ 重点战略信号                                                   │
│ [扩张] 可能扩大海外商业化投入   招聘 → 营销 → 网页  中置信度  │
│        事实摘要 · 可能含义 · [展开证据链]                     │
│ [承压] 用户反馈集中在……        用户之声 → 销售       高优先  │
│ [转向] …                                                      │
├─────────────────────────────────────────────────────────────┤
│ 战略时间线：招聘新增 ── 用户反馈变化 ── 网页动作 ── 销售响应 │
│ [查看事实/研判] [只看跨板块] [只看高置信度]                  │

```

视觉隐喻是“战略雷达/指挥台”，不是公司的真实组织结构图：中心显示姿态，外围显示证据源，连线只代表经过校验的关联。人数区间、部门区间、地区区间和模型方法放入二级抽屉：点击信号的“证据链”，再进入“组织详情/估算方法”。

## 5. 关键交互

1. 默认加载 `all_history`，页面上明确显示完整日期范围；用户可切换最近 30/90 天或自定义窗口。
2. 点击信号卡进入二级抽屉，按“观察到的事实 → 可能意味着 → 替代解释 → 下一步验证”顺序展示。
3. 点击域标签只过滤证据，不改变模型原始结论；过滤后如果不再满足跨板块门槛，应显示“当前筛选不再满足交叉证据条件”。
4. “事实 / 研判”切换使原始证据与模型文字分层，避免用户把推断当成数据。
5. “组织详情”展示现有招聘雷达、可见员工下界、部门/地区区间；所有数字带估算、来源和限制标签。
6. 一级屏只展示 3 条以内核心信号，剩余结果通过“查看更多”进入详情列表，保证单屏可读。

## 6. 模型输出与二级组织详情

一级模型只输出 `summary/signals/caveats`；不得在一级文案中生成伪精确人数。

二级 `organization_estimate` 可复用现有招聘人数估算契约：

```json
{
  "overall": {"low": 0, "high": 0, "confidence": "low", "basis": []},
  "departments": [{"department": "技术研发", "low": 0, "high": 0, "confidence": "medium", "rationale": "", "evidence_ids": []}],
  "locations": [{"city": "San Francisco", "low": 0, "high": 0, "confidence": "low", "rationale": "", "evidence_ids": []}],
  "assumptions": [],
  "limitations": []
}
```

必须保留以下边界：招聘需求不等于员工数；LinkedIn 人员是可见样本下界；没有充分证据时宁可不输出区间；所有区间都提供 evidence IDs、假设和限制。

## 7. 最小测试清单

### 后端契约

- `scope=all_history` 返回所有可用板块的最小/最大有效日期，并不被招聘时间筛选器覆盖。
- 空数据库返回 `signals=[]`、各板块 `status=empty` 和清晰 caveat，不返回伪结论。
- 只有招聘证据时，结果可以有招聘观察，但不能生成跨板块战略信号。
- 招聘 + 用户之声 + 营销证据通过两个独立来源组门槛后，才允许生成跨板块信号。
- 非法/不存在 `evidence_ids` 被过滤；模型引用不能指向输入之外的记录。
- 模块汇总与其原始记录不被重复计为独立证据。
- 批量相同时间戳产生 caveat，不生成集中发布结论。
- 全量历史抽样和缓存键稳定，重复请求不重复调用模型。

### 前端单屏

- 首屏同时显示范围、姿态、总判断、最多 3 条信号和覆盖状态。
- 信号卡的事实、研判、置信度和来源标签可区分。
- 点击证据链能打开二级详情并跳转原模块。
- 过滤到单板块后，页面提示交叉证据门槛不再满足。
- 无数据、部分数据、加载失败和模型未配置都有明确状态。
- 1366px 桌面与窄屏下不产生横向溢出；二级证据链可滚动。

### 回归

- 现有 `/api/overview/summary` 与经营总览洞察结果保持兼容。
- 现有招聘 `业务动向分析` 仍只解释招聘/JD，不被新的跨板块模块替代。
- 现有招聘组织雷达和人数估算的证据边界继续生效。

## 8. 需要拍板的产品点

1. 一级正式名称：`组织与战略信号`、`战略雷达`，还是保留“组织推演台”作为视觉名称。
2. 只放在招聘页业务动向分析下，还是同时在经营总览提供同一结果的摘要入口。
3. 全量历史是否允许跨多年；数据量较大时是否默认限制最近 365 天。
4. 人数估算是否始终需要用户点击后生成，还是在已配置模型时自动生成二级结果。
5. 视觉风格是偏严肃战略驾驶舱，还是保留较明显的雷达/组织树趣味化表达。
6. 跨板块信号最低门槛是否固定为两个独立来源组，还是提供严格/宽松模式。
